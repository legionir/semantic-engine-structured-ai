## Findings قطعی و وضعیت اطمینان

### قطعی (evidence verbatim + path/line)

1. تاریخچهٔ Git ذاتاً سقف‌دار است: `GitClient.ts:400–405` می‌گوید `maxCommits` سقف دارد و `GitClient.ts:502–506` مقدار `truncated` را بر اساس سقف برمی‌گرداند. این یک محدودیت طراحی مستند است، نه bug امنیتی.
2. `GitInfoCollector.collectFileMetrics` وضعیت truncation را در قرارداد/خروجی خود ندارد: interface در `GitInfoCollector.ts:14–17` فقط `metricsByPath` و `maxCommitCount` را تعریف می‌کند و return در `156` نیز همین دو را برمی‌گرداند؛ در حالی که `GitClient.RepositoryHistory` در `GitClient.ts:44–51` فیلد `truncated` دارد.
3. تست‌های build-gated واقعاً conditional هستند: `serve-watch.test.ts:21–22`، بنابراین نبود `dist/cli/main.js` آن suiteها را skip می‌کند.
4. همهٔ ۲۰ فایل در زمان ممیزی وضعیت `درانتظار` داشتند و پس از این گزارش فقط همین ۲۰ مورد به `کامل` تغییر داده شدند.

### POTENTIAL/UNVERIFIED (قطعی اعلام نشده)

- مرز prefix در `GitClient.ts:460–462` با `startsWith` ممکن است false match بدهد؛ fixture/test برای sibling prefix نداریم.
- `truncated` در مرز دقیق سقف (`>=`) ممکن است false-positive باشد؛ تست مرزی نداریم.
- export نشدن چند interface از `core/git/index.ts` و نبود validation در `FileIdGenerator.seed` فقط potential هستند چون consumer/public API requirement در شواهد این batch ثابت نشد.
- هیچ finding امنیتی گزارش نشد؛ امنیت صراحتاً خارج از scope بود.
