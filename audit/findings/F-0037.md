# F-0037 — constructors reported their own class name as `returnType`

- **Severity:** LOW
- **Plan:** C-x (this-cycle), plan id `f0037`
- **Status:** FIXED-VERIFIED (2026-10-06)

## Finding
Tree-sitter's constructor nodes (`constructor_declaration` in Java/C#,
`constructor_definition` in TypeScript) carry a *type* child that is simply the
containing class name — it is not a return type. The symbol mapper read it
verbatim, so every constructor in every language reported
`returnType: <ClassName>`, polluting the type graph and any UI/impact logic that
trusts `returnType`.

## Fix
The mapper detects constructor nodes (`isConstructorNode` in
`src/symbols/tree-sitter/TreeSitterSymbolMapper.ts:418`) and suppresses the
`returnType` field for them, in every grammar.

## Evidence
`src/symbols/tree-sitter/multiLanguage.seSym20.test.ts` asserts, per language,
that constructor symbols have `returnType: null` while ordinary methods keep
theirs. Suite green under `tsc --noEmit` and `jest --ci` (full-suite run
2026-10-07).
