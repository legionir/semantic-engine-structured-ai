# F-0036 — `get_dependencies` backward parity with impact/explain

- **Severity:** MED
- **Plan:** C-x (this-cycle), plan id `f0036`
- **Status:** FIXED-VERIFIED (2026-10-06)

## Finding
`get_dependencies` with `direction: 'backward'` read only the
`reverseDependencyGraph` file-level edges, while `impact_analysis` /
`explain_symbol` roll up from the call graph, whose edges terminate at
**symbol** nodes. For a method with many callers, `get_dependencies` therefore
returned fewer (or zero) dependents than `impact_analysis` for the same seed —
the two tools disagreed on the same question. Measured on the engine's own
index: `get_dependencies` 1 item vs `impact_analysis` 4 items for
`ContextRanker.rank`.

## Fix
Backward dependencies now roll up from `reverseDependencyGraph` **and** call
edges, at symbol level, so the emitted set matches `impact_analysis` /
`explain_symbol`. Duplicate rows per file are collapsed into one item with a
`dependents` count and `viaSymbols` provenance.

## Evidence
Regression suite `src/ai/tools/GetDependenciesTool.test.ts` (F-0036 block):
caller-file set equals `impact_analysis`'s; one row per file with counts;
`level:'symbol'` yields the intermediate symbols; suite green under
`tsc --noEmit` and `jest --ci`.
