# پلن اجرایی: ایجنت کدنویسی روی سرور حداقلی

## هدف

کاربر روی یک سرور کوچک (VPS ارزان، بدون Docker) یک ایجنت قدرتمند داشته باشد و کار پروژه‌هایش را به آن بسپارد، بی‌آنکه کامپیوتر خودش را درگیر کند.
تجربهٔ مطلوب مثل این است که چند پنجرهٔ ایجنت هم‌زمان باز باشد و هر کدام در مسیر یک پروژه کار کند:

```
/srv/projects/proj1   ← گفتگوی ۱
/srv/projects/proj2   ← گفتگوی ۲
/srv/projects/proj3   ← گفتگوی ۳
```

## اصول

1. **سرور حداقلی:** بدون کانتینر و sandbox در مرحلهٔ اول. هیچ قابلیتی نباید به Docker یا سخت‌افزار قوی نیاز داشته باشد.
2. **هستهٔ سبک، اتصال از راه MCP:** GitHub، Linear، مرورگر (Playwright)، جستجوی وب و بقیهٔ سرویس‌ها داخل برنامه پیاده نمی‌شوند. زیرساخت MCP محکم می‌شود و یک کاتالوگ آماده با فعال‌سازی یک‌کلیکی ارائه می‌شود.
3. **امنیت بدون ایزوله‌سازی:** چون sandbox نداریم، محصورسازی مسیر هر پروژه، پاک‌سازی متغیرهای محیطی، policy و تأیید کاربر باید جدی‌تر باشند.
4. **قواعد مخزن (CLAUDE.md):**
   - بدون build step و بدون وابستگی سنگین.
   - هر فایل زیر ۵۰۰ خط.
   - اعتبارسنجی ورودی در مرزها.
   - هر تنظیم جدید در `agent/config/settings-definitions` و جدول README ثبت شود.
5. **هر فاز یک PR جدا.** هر قلم کار با تست واحد یا مسیر (route) همراه است و قبل از merge باید `ci/run-tests.js` کامل سبز شود.

## راهنمای خواندن

- **ارزش و پیچیدگی:** بالا، متوسط یا کم.
- **وابستگی:** شناسهٔ قلم‌هایی که باید قبل از این قلم انجام شوند.
- **ترتیب:** فازها به‌ترتیب اجرا می‌شوند. داخل هر فاز، قلم‌ها بر اساس نسبت ارزش به پیچیدگی مرتب شده‌اند.
- **فاز ۷** شامل موارد کانتینر و sandbox است که برای بعد ثبت شده‌اند تا فراموش نشوند.

## وضعیت فعلی (پایه‌های موجود)

**آنچه داریم:**
- **پنل و پروژه‌ها:**
  - پنل وب چندپروژه‌ای و اجرای موازی پروژه‌های مختلف (`web/server/console/task-runner.js`).
  - لاگ سراسری، ترمینال و مدیریت فایل (PR #38).
- **ایجنت و مدل‌ها:**
  - ۸ ارائه‌دهندهٔ مدل.
  - ساب‌ایجنت‌ها و بحث چندپرسونایی.
  - ابزار برنامه‌ریزی، حافظه، آرشیو، `checkpoint_undo`، hook و skill.
- **امنیت و پایداری:** policy و تأیید کاربر، و ثبت رویدادها (eventstore و journal).
- **MCP:**
  - چهار نوع اتصال، پیکربندی `.mcp.json`، اعتبارسنجی و سیاست اعتماد.
  - افزودن، حذف و روشن/خاموش کردن سرورها از پنل.

**کمبودهای مهم:**
- **یک گفتگو در پیش‌زمینه:** پنل فقط یک گفتگو را در پیش‌زمینه نشان می‌دهد، و شروع اجرای دوم در پروژه‌ای که مشغول است با خطای 409 رد می‌شود.
- **MCP:**
  - تصویرِ برگشتی از ابزار MCP به مدل نمی‌رسد.
  - resources و prompts فقط در لایهٔ اتصال پیاده شده‌اند.
  - OAuth، elicitation (درخواست ورودی از کاربر توسط سرور MCP) و کاتالوگ آماده نداریم.
- **دستورالعمل پروژه:** فایل‌های `AGENTS.md` و `CLAUDE.md` خوانده نمی‌شوند.
